# 39 · 内置免费 AI 能力方案（无 API Key 也能用）

> 版本：草案 v0.1　日期：2026-11-08　适用版本：0.2.18+
> 目标读者：产品 / 前端 / Electron 主进程 / 后端
> 状态：方案待评审，未落地代码

---

## 1. 背景与目标

当前知序的 AI 能力（对话、事项解析、润色、文档分析）**全部依赖用户自己配置供应商 API Key**（DeepSeek 或自定义 OpenAI 兼容接口）。没配 Key 时走 `本地规则`：只能做正则式提取和固定话术，体验与"真 AI"差距明显。

**目标**：让**没有配置任何 API Key 的用户**，开箱即可获得接近真实模型的 AI 能力，从而"也能进行操作"（对话理解、任务提炼、润色、文档拆解）。

**拆解为三个子目标**：

1. **可用**：零配置即可完成核心操作，而不是只能手动管理。
2. **可控**：免费额度、限流、成本可管理，不因滥用拖垮项目。
3. **可退**：失败时自动降级到本地规则；用户随时可切换回自有 Key。

> 重要判断：**"进行操作"这件事本地规则今天已经能做到一档**（见第 2 节）。所以本方案真正的增量是**把本地规则升级为真实模型**，而不是从 0 到 1。这决定了我们应当"替换/增强 local 分支"，而不是新造一套并行体系。

---

## 2. 现状盘点（代码层面）

### 2.1 供应商配置的唯一入口

`prototype/shared.js` 的 `aiProviderConfig()` 是全局唯一判定：

- 有自定义供应商（baseUrl + apiKey + model）→ `{ id:'custom', ... }`
- 有 `settings.deepseekKey` → `{ id:'deepseek', ... }`
- 都没有 → `{ id:'local', name:'本地规则', baseUrl:'', apiKey:'', model:'' }`

`hasAIProvider()` 等价于 `id !== 'local'`。**几乎所有 UI 判断都依赖这个 `id === 'local'`**。

### 2.2 四个 AI 能力入口

| 能力 | 前端入口 | 主进程 | 无 Key 时行为 |
|---|---|---|---|
| 对话 | `views-chat.js` `sendChat()` | `chat.ts` → `providerText()` | `buildChatReply()` 固定话术 + 快捷按钮 |
| 事项解析 | `modals.js` 快速捕获 | `capture.ts` → `providerText()` | `deriveCaptureTitle()` 取前若干字 |
| 润色 | `views-chat.js` `requestAIPolish()` | `polish.ts` → `providerText()` | 本地规则替换/不动 |
| 文档分析 | `documents.js` `analyzeImportedDocument()` | `document-analysis.ts` | `localAnalysis()` 行动语句正则提取 |

四个入口最终都收敛到 `providers.ts` 的 `providerText(value, messages, options)`，而它第一行就是 `providerSchema.parse(value)`——**`apiKey` 是必填（min 1）、`model` 必填**。这是接入内置模式的天然改造点。

### 2.3 结论

- 最小侵入的做法：**让"内置免费"伪装成一个标准的 ProviderConfig**（有 baseUrl、有 apiKey、有 model），这样 `chat/polish/capture/document-analysis` 四条链路**一行都不用改**。
- 只需在 `aiProviderConfig()` 里新增一个 `builtin` 分支，把 `baseUrl` 指向知序的中转网关、`apiKey` 填匿名设备令牌、`model` 填一个别名即可。

## 3. 约束与红线

1. **客户端无法安全保存密钥**：任何打包进安装包的 API Key 都能被逆向提取。所以"内置免费 API"**不能**把上游厂商的 Key 写进客户端，**必须经过知序自己（或可控第三方）的中转**。
2. **与"本地优先"品牌叙事冲突**：README/PRD 明确"不使用知序自有云端后端""项目、任务、聊天记录留在本机"。内置免费模式一旦启用，**对话内容会发到中转服务器**。这与现有定位直接矛盾，必须由产品决策，并在 UI 上**显式告知 + 首次同意**，不能静默开启。
3. **合规**：面向公众提供生成式 AI 服务，在中国境内涉及算法备案、内容安全审核、日志留存等要求。若仅个人/内测自用，风险较低但仍需内容过滤。
4. **成本与滥用**：免费额度本质是补贴。必须有匿名设备维度 + IP 维度的限流、日配额、单请求 token 上限、成本告警。
5. **可持续**：内置免费是"体验入口"，产品目标是**把重度用户引导到自有 Key 或付费**，而不是长期白嫖。

## 4. 三条技术路线对比

| 维度 | A. 官方免费中转网关 | B. 端侧小模型（ONNX / llama.cpp） | C. 聚合第三方免费额度 |
|---|---|---|---|
| 实现方式 | 自建/托管一个 OpenAI 兼容中转，服务端保管上游 Key | 安装包内置小模型，本地推理 | 客户端或中转直连各厂商免费模型 |
| 质量 | 好（可用主流小/中模型） | 一般（0.5B~1.5B 量化，中文可用但弱） | 中~好（取决于免费模型） |
| 隐私 | 中（内容出本机到中转） | **最好（完全离线）** | 差（内容出本机） |
| 离线 | 否 | **是** | 否 |
| 边际成本 | 有（按量，可控） | **≈0** | 低但有额度上限 |
| 包体/性能 | 无 | 增大 300MB~1.5GB，吃 CPU/RAM，首 token 慢 | 无 |
| 实现复杂度 | 中（要运维后端） | 高（跨平台推理、打包、兼容） | 中（要隐藏 Key，仍需中转） |
| 合规 | 需备案 | 相对轻（端侧） | 需自行承担上游条款风险 |
| 可持续 | 需预算 | 最稳 | 免费额度易变、易被限 |

**结论**：主路线选 **A（官方免费中转）**，因为质量/体验最好、实现最可控；**本地规则**作为永久兜底；**B（端侧小模型）**作为后续"离线/隐私增强包"可选，不作为首版主线。**C 只作为 A 的上游选型手段，不直接把厂商 Key 放客户端。**

## 5. 推荐方案（分层）

```
用户在 设置 里三选一：内置免费 / 自有 DeepSeek / 自定义
        │
        ▼
aiProviderConfig()
   ├── id='builtin' → baseUrl=知序中转, apiKey=设备令牌, model='zhixu-free'（本次新增）
   ├── id='deepseek' → 现有逻辑
   ├── id='custom' → 现有逻辑
   └── id='local' → 本地规则（默认兜底；内置关闭或额度用尽时回退）
        │
        ▼
providerText()  →  中转网关  →  上游免费模型（智谱/阿里/硅基/Cloudflare…）
                         └── 失败/超配额 → 返回结构化错误 → 前端降级 local
```

### 5.1 "零侵入"接入

在 `shared.js` 的 `aiProviderConfig()` 最前面加：

```js
const builtin = s.builtinAI || {};
if (builtin.enabled !== false && builtin.token) {
  return {
    id: 'builtin',
    name: '知序内置免费',
    baseUrl: String(builtin.baseUrl || 'https://ai.zhixu.app/v1').replace(/\/+$/, ''),
    apiKey: String(builtin.token),
    model: String(builtin.model || 'zhixu-free'),
    protocol: 'chat',
    detected: '知序内置'
  };
}
```

这样 `chat.ts / polish.ts / capture.ts / document-analysis.ts` **全部无需改动**，直接复用现有的重试、超时、脱敏、校验逻辑。

### 5.2 设备令牌与匿名身份

- 首次使用时，主进程生成/获取**匿名设备标识**：`sha256(machineId + 安装盐)`，不含个人信息。
- 两种实现：
  - **MVP**：不回注册，直接以 `X-Zhixu-Device: <设备标识>` + 请求 IP 做限流；令牌可放一个安装期随机串。
  - **增强**：中转提供 `/register` 返回签名令牌（含配额、过期），主进程存到 `settings.builtinToken`（可用 safeStorage 加密）。
- **不做账号体系**，避免收集手机号/邮箱。

### 5.3 上游免费模型候选（**额度与条款以官方最新为准，需逐项核实**）

| 上游 | 候选模型 | 中国大陆可达 | 兼容性 | 备注 |
|---|---|---|---|---|
| 智谱 | GLM-4-Flash / GLM-4.5-Flash | 好 | OpenAI 兼容 | 官方长期有免费档，首选 |
| 阿里云百炼 | qwen-flash / qwen-turbo | 好 | OpenAI 兼容 | 有免费额度/限时活动 |
| 硅基流动 | 部分小模型免费 | 好 | OpenAI 兼容 | 免费型号池会变 |
| Cloudflare Workers AI | Llama/Qwen 小模型 | 一般 | 自有 API | 有每日免费 neuron 配额，适合作中转后端 |
| OpenRouter | `:free` 模型 | 需海外网络 | OpenAI 兼容 | 限流严格，条款需核对 |
| Groq | Llama 系列 | 需海外网络 | OpenAI 兼容 | 免费额度快、但地区受限 |
| Google Gemini | Gemini Flash | 需海外网络 | 自有 REST | 有免费层，地区限制 |

> 选型原则：**面向国内用户优先国内厂商**（延迟低、可达性好、合规可控）；跨境模型只做备份路由。

### 5.4 配额与降级

- 每日免费额度（如 20~50 次对话 / 200 次轻量调用），额度用尽：
  1. 提示"今日免费额度已用完"，给出**一键配置自有 Key**入口；
  2. 自动降级到 `local` 规则，保证功能不中断。
- 单请求 token 上限：复用现有 zod 长度上限（如单条 ≤ 20000 字），中转再做硬截断。
- 失败分类：网络/5xx → 降级 local；401/403/配额 → 明确提示切自有 Key。

## 7. UI / 交互方案

设置 → 模型与供应商，改为三张卡片：

1. **内置免费（推荐给新用户）**：显示"今日剩余 X 次 / 已用 Y"，开关默认开；首次开启弹隐私确认。
2. **DeepSeek**：现有快速接入。
3. **自定义**：现有。

对话页：模型标签显示 `知序内置免费 · zhixu-free`；额度不足时气泡内提示"今日免费额度已用完，点此配置自有 Key 或继续用本地规则"。

首次隐私弹窗（关键）：
> "内置免费模式会将你发送的内容转发到知序的免费中转服务，由其所接入的模型供应商处理。若你更在意隐私，可在设置中改用本地 Ollama/自定义接口，或关闭内置模式只用本地规则。"

## 9. 最小可行替代（暂不自建后端时）

如果短期内没有后端资源，可先用 **Cloudflare Worker 代理 + 单一国内免费上游** 打通：

```
客户端 → Worker(/v1/chat/completions, 校验设备头+KV 计数器)
        → 上游（如 智谱 GLM-4-Flash 或 Workers AI）
```

- Worker 保管上游 Key，KV 记录每日配额，超限返回 429。
- 优点：当天可上线；缺点：免费额度不稳、Worker 在境内可达性一般、长期仍需正式网关。

## 10. 需要你拍板的决策点

1. **是否接受"内置模式内容经知序中转"**？这会修改"本地优先/不使用自有云端"的对外表述。🅿️
2. **是否有可用的后端/云账号与每月成本上限**（决定 P1 能否真机连通）？
3. **首批覆盖能力**：对话 / 捕获 / 润色 / 文档分析，全部上还是先做对话+捕获？
4. **是否要端侧离线小模型**（体积与性能代价大，建议 P3 再议）？
5. **数据留存策略**：中转是否记录正文（建议不记录/仅脱敏 24h）？

## 11. 决策更新（v0.2）：改为「小额体验 + 引导获取免费 Key」混合模式

评审后确认：**知序自建的免费中转额度有限、长期成本不可持续，且每次用户都消耗我们的额度。** 更健康的产品形态是分层：

| 层级 | 形态 | 谁承担成本 | 定位 |
|---|---|---|---|
| L1 体验 | 内置免费 AI（Worker 中转，每日限量） | 知序 | 首次上手、零配置演示 |
| L2 主力 | **引导用户注册国内免费/低价厂商，粘贴自己的 Key** | 用户（厂商免费额度） | 长期可持续、隐私更好 |
| L3 自定义 | 任意 OpenAI 兼容接口 | 用户 | 高级用户 |

已实现的「免费 Key 获取向导」：

- 设置页 / 内置卡片提供入口「获取免费 API Key」，列出国内厂商（智谱 GLM、阿里百炼、硅基流动、DeepSeek、Moonshot）。
- 每个厂商给出注册/密钥链接、免费额度说明、默认 API 地址与模型、分步指引。
- 用户粘贴 Key → **真实测试一次 → 自动保存为自有供应商**，之后优先使用自己的 Key，不再经过知序中转。
- 外链通过主进程白名单打开（仅 https + 指定厂商域名 + GitHub 仓库）。

这样把「体验」和「长期使用」都照顾到：新用户零门槛先体验，额度用尽或想长期用时，一句话引导到自己的免费 Key。
