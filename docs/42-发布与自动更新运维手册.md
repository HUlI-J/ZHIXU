# 知序 · 发布与自动更新运维手册

本文记录 0.2.19 发布卡住的根因、修复方式与后续标准流程。面向维护者。

## 1. 自动更新如何工作

桌面端使用 `electron-updater` 的 GitHub provider：

1. 客户端向 `https://api.github.com/repos/HUlI-J/ZHIXU/releases/latest` 查询**已正式发布**的 Release。
2. 读取该 Release 里的 `latest.yml`，得到版本号、安装包 URL 与 `sha512`。
3. 版本更高则后台下载，校验 `sha512` 通过后提示用户重启安装。

关键前提：**只有已发布（非草稿、非预发布）且带齐资源的 Release 才会被识别。** 仅推送 git tag、或把 Release 留在草稿状态，客户端永远看不到新版本。

## 2. 0.2.19 发布卡住的根因

2026-11-16 排查确认：

| 检查项 | 实际状态 | 影响 |
| --- | --- | --- |
| `v0.2.19` git tag | 已存在 | 代码已更新 |
| `v0.2.19` GitHub Release | **草稿**（`draft: true`，`published_at: null`） | 更新源不可见 |
| Release 资源 | **0 个** | 即使发布也没有 `latest.yml` |
| 上传请求 | 返回 `Multipart form data required`，未重试 | 上传步骤失败后流程中断 |
| Release 标题 | 乱码 `鐭ュ簭 0.2.19` | PowerShell 5.1 把 UTF-8 无 BOM 的 `.ps1` 当 GBK 读取 |
| 仓库所有者拼写 | 代码里写成 `HULI-J`，真实 login 是 `HUlI-J` | 大小写不一致，潜在隐患 |
| `latest.yml`（v0.2.17） | 正确 | 客户端因此一直认为 0.2.17 是最新版 |

结论：不是版本号检测、签名或发布格式的问题，而是**发布流程未完成**——Release 停留在草稿且资源为空。

## 4. 标准发布流程（二选一）

### 方式 A：GitHub Actions（推荐）

1. 通过 PR 合并版本变更到 `main`，确认 `package.json` 版本与目标一致。
2. 在 Actions 页运行 **Release Desktop**，填写版本号与发布说明路径。
3. 流水线自动构建、上传、发布并复核 `releases/latest`。

### 方式 B：本地脚本

在 Windows、项目根目录执行：

```powershell
npm run dist
powershell -File scripts/publish-release.ps1 -Action create
powershell -File scripts/publish-release.ps1 -Action upload
powershell -File scripts/publish-release.ps1 -Action publish
powershell -File scripts/publish-release.ps1 -Action verify
```

任一步失败可先诊断：

```powershell
powershell -File scripts/publish-release.ps1 -Action status
```

## 5. 发布后自检清单

- [ ] `https://api.github.com/repos/HUlI-J/ZHIXU/releases/latest` 返回目标版本
- [ ] `draft: false`、`prerelease: false`、`published_at` 有值
- [ ] 5 个资源齐全，`state: uploaded`
- [ ] `latest.yml` 的 `version` 与 Release tag 一致，安装包 `sha512` 与本地文件一致
- [ ] Release 标题与正文无乱码
- [ ] 客户端“设置 → 关于/更新”点击“检查更新”能发现新版本

## 6. 客户端为何仍停在 0.2.17？

如果你现在的客户端还显示旧版本：

1. 桌面端启动 15 秒后自动检查一次，之后每 6 小时检查一次；可在设置里手动点“检查更新”。
2. 自动更新开关若被关闭，请打开后它会立即检查一次。
3. 检查 `HTTPS_PROXY` / 系统代理配置；更新请求走 Electron 的 net session 代理。
4. 若网络正常且仍看不到 0.2.19，请确认客户端版本确实是从官方 Release 安装的正版安装包（开发预览模式不会安装更新）。
